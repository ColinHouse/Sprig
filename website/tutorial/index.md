# Sprig 程序设计语言

欢迎。这本书从零开始讲 Sprig：一门跑在 JVM 上、语法像 Python、类型检查像一位严格但讲道理的老师的小语言。

每一章讲一个主题，章与章之间按顺序递进。书里的每一段代码都由仓库的文档检查真实运行过，代码下面的输出就是它运行时打印的内容；每一段"故意写错"的代码也都真实地被编译器拒绝过，报错信息原样照录。

## 这本书写给谁

写给已经会一门编程语言的人。你用过 Python、JavaScript 或 Java 中的任意一门，知道变量、函数、列表和类是什么，这本书就读得下去。不需要会 Java，也不需要了解 JVM；真正需要 Java 知识的只有第 13 章。

如果你还没写过程序，这本书会快一些，但每章的练习和故意写错的例子会帮你慢下来。

## Sprig 是什么样的语言

先看一个完整的程序：

<<< @/snippets/book/ch09_errors.spr

```text
42
failed: not a number: abc
done
```

这十几行里已经有 Sprig 的几个核心主张：

- **缩进就是结构。** 没有花括号，没有分号，一行写一件事。
- **类型写在签名上，推断留给局部。** 函数的参数和返回值都要写类型；函数体里的 `let value = ...` 不用。
- **可能失败的事写进类型。** `throws Error` 是签名的一部分，调用方要么处理，要么也声明。没有悄悄传出去的异常。
- **可能为空的值也写进类型。** `toIntOrNull()` 返回 `Int?`，判断过 `== null` 之后才能当成 `Int` 用。
- **没有隐式转换，没有"非零即真"，没有兜底分支，没有继承。** 这些在后面的章节里会一个个遇到。

Sprig 的另一个设计目标是：编译器的报错要能直接读、直接照着改，并且有结构化（JSON）形式，方便编辑器和 AI 编程助手使用。所以这本书会把报错当作正文的一部分，而不是附录。

## 怎么读这本书

全书十六章，分成三个部分：

| 部分 | 章 | 内容 |
|---|---|---|
| 基础 | 1 – 5 | 安装、值与类型、控制流、函数、集合 |
| 类型系统 | 6 – 11 | 类、枚举与 variant、可空值、错误、泛型、函数值 |
| 工程与生态 | 12 – 16 | 模块与项目、Java 互操作、并发、工具链、一个完整项目 |

按顺序读是最省力的，后面的章节会直接用前面讲过的东西。已经熟悉静态类型语言的读者可以跳过第 2 到第 4 章，但请不要跳过第 8 章（可空值）和第 9 章（错误），那两章讲的是 Sprig 和大多数语言不一样的地方。

书里的约定：

- 代码块下面紧跟的 `text` 块是运行结果。
- 标着"故意写错"的小节里，代码**不能**通过编译，下面的 `text` 块是编译器的报错。报错开头的 `SPR-...` 是错误码，`sprig explain 错误码` 会给出完整解释。
- 书中的每个例子都可以粘进一个 `.spr` 文件，用 `sprig run 文件名` 直接运行。
- 这里讲的是 Sprig 的最新源码。如果你装的 SDK 旧一些，个别报错的措辞可能不同，错误码不变。
