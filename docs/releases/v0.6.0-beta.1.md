# Sprig v0.6.0-beta.1

Sprig **v0.6.0-beta.1** is the second Beta SDK. It adds a language server, a
built-in `Comparable` capability and a larger bundled standard library, and it
fixes correctness gaps found by adversarial probes and recorded coding-agent
sessions. It is an experimental Beta, not a promise of production stability or
a frozen API. The compiler is **0.6.0-beta.1**; the language version remains
**0.8-dev**. JDK 17+ is required. Linux and macOS are release-supported;
Windows remains an experimental, non-blocking preview.

## Highlights

### Language server

- `sprig lsp` speaks the Language Server Protocol over standard input and
  output, so Neovim, Helix and other LSP clients can use it. It runs inside the
  compiler and reuses its parser, name resolver, type checker and formatter.
- It provides diagnostics as you type, hover with checked types, go to
  definition across modules, references, document symbols, completion,
  formatting, and rename of local variables and parameters. A rename is
  refused if compiling the renamed text would change what any name refers to.
- Files in a project use the project's locked dependencies and classpath.
  The server never resolves or downloads anything. When the current text
  doesn't get far enough through the compiler, a request returns nothing
  rather than a guess.
- Setup for Neovim and Helix is in `docs/LANGUAGE_SERVER.md`. The VS Code
  extension 0.3.0 in the repository's `editors/vscode` starts the server
  automatically; it is built from source and is not part of the SDK archive.

### Language and type checking

- `requires T: Comparable` is implemented. It grants `<`, `<=`, `>` and `>=`
  between values of `T` and `sort()` on a `MutableList[T]`. `Int`, `Int32`,
  `Float`, `Float32`, `Decimal`, `BigInt` and `String` qualify, as does a type
  parameter that itself requires `Comparable`. It is a closed, built-in
  capability: there are no user-defined capabilities or traits.
- Null checks now narrow inside `and`/`or` conditions:
  `if box != null and box.value > 0:` and
  `if text == null or text.length() == 0:` are accepted.
- A generic function can call a callable parameter whose result is a concrete
  type, such as `accept: fn(T) -> Bool`. Such programs used to pass
  `sprig check` and then fail in `javac`.
- Top-level code can no longer use a binding declared below it
  (`SPR-NAME-FORWARD-REFERENCE`). A function, method, lambda or field default
  that reads a top-level binding before its initializer has run fails with
  `SPR-RUNTIME-EXCEPTION` at the use site instead of observing `0` or `null`.

### Standard library

| Module | What's new |
|---|---|
| `@std/lists` (new) | `sort_by`, `group_by`, `fold`, `find`, `any`, `all`, `count`, `sum`, `sum_by`, `sorted` over `List[T]` |
| `@std/nulls` (new) | `or_else` for a fallback value, `require` to throw `Error(message)` for `null` |
| `@std/math` (new) | `Int` helpers `abs`, `min`, `max`, `sign`, `clamp`, `floor_div` and `isqrt`; invalid input such as a zero divisor throws `Error` |
| `@std/json_codec` (new) | Typed JSON field readers and builders, moved from the `sprig-json-codec` package so single files and new projects can use them; adds `root_array` |
| `@std/text` | `pad_left`, `pad_right`, `is_ascii_digit`, `is_ascii_letter` |
| `@std/test` | `equal_int`, `equal_bool`, `equal_text`, whose failures name both values |
| `@std/process` | `exit` to choose the exit status, `print_error` for standard error, and `read_line`, `read_lines` and `read_all` for standard input |

The `sprig-json-codec` package keeps working as a facade over
`@std/json_codec`, and it gains string-array and optional nested object and
array helpers.

Piped standard input is read as UTF-8. With `--json`, `sprig run` reports what
the program wrote to standard error as `programErrorOutput`, and the program
reads an empty standard input.

### Gradle and Fabric

- The SDK includes the `dev.sprig` Gradle plugin as source
  (`libraries/sprig-gradle`). A host build selects a source set, and
  `./gradlew check` runs Sprig checks and tests while `build` and run tasks
  get the generated Java.
- `libraries/sprig-fabric/template` is a Fabric/Loom starter that uses it.
- `sprig test --classpath` passes a build tool's real classpath to Sprig tests.

### Correctness and diagnostics

- Runtime failures and `javac` errors pointed at the statement after the
  failing one whenever another statement followed. They now point at the
  failing line.
- Programs that pass `sprig check` no longer fail in `javac` because of names
  that are special in Java: enum or variant cases such as `default` and `new`,
  methods such as `wait` and `hashCode`, and identifiers spelled like a Java
  package root.
- Code after a `while true` loop without `break` is reported as unreachable;
  it used to pass `sprig check` and then fail in `javac`. Very long string
  literals are split to fit the class-file limit, and a method that is too
  large for the JVM gets an actionable hint.
- `help numerics` lists the explicit numeric conversions, and
  `SPR-NUM-CONVERSION` hints name the method for each pair. A nullable member
  error points at the member and names the receiver type. A function that
  writes `throws` without a result type gets an explanation instead of a raw
  parser error.
- A project reached through a symlinked path, such as macOS `/var` and
  `/private/var`, no longer loses its package imports.
- `sprig init .` names the project after its directory instead of `.`.

### Performance

The launchers start the compiler JVM with the C1 JIT only
(`-XX:TieredStopAtLevel=1`), because commands finish before the C2 compiler
pays off. In the measurements in PR #84 (Windows 11, JDK 17 and 25), `run`,
`build` and `test` were 27–43% faster. `sprig lsp` keeps tiered compilation,
and programs started by `sprig run` and `sprig test` keep the JDK's defaults.

### Windows preview

The Windows workflow now runs every gate instead of continuing past failures,
and the bugs it exposed are fixed: projects reached through 8.3 short names or
junctions, manifests checked out with CRLF, escaped absolute paths in locks,
non-UTF-8 redirected output on JDK 19+, `!` in arguments to `sprig.cmd`, and
CRLF documents in the language server. Windows is still a preview, not a
release-supported platform.

## Upgrade from v0.5.0-beta.1

On a managed Linux/macOS installation, run `sprig upgrade --check` and then
`sprig upgrade`. The installer verifies the published checksum and archive
before switching SDKs; older installed versions remain available. A manual
installation can use the ZIP and `.sha256` file from the
[release page](https://github.com/ColinHouse/Sprig/releases/tag/v0.6.0-beta.1).

Then run `sprig resolve` in each project root:

- Project locks now use schema 5, which no longer records the bundled `@std`.
  Locks written by v0.5.0-beta.1 use schema 4 and are rejected with
  `SPR-PROJECT-LOCK-SCHEMA`.
- A lock now has to match the running compiler. A lock written by another
  compiler version is reported as `SPR-PROJECT-LOCK-STALE`.

The first Maven resolution may need network access; later operations can use
the verified cache with `--offline`.

`sprig check` now rejects top-level code that reads a binding declared below
it, which v0.5.0-beta.1 accepted. A function called before a top-level
binding's initializer has run now fails with `SPR-RUNTIME-EXCEPTION` instead
of reading `0` or `null`. `sprig fmt` now writes named arguments as
`name=value`, so `sprig fmt --check` reports files that use `name = value`.
Re-run your project's checks and tests after upgrading.

## Known limits

- This is an experimental Beta, not production-ready software or a guarantee of
  source, binary, or API stability.
- Windows is not release-supported.
- Generic calls need explicit type arguments, such as `lists.find[Order](...)`.
  There is no generic type inference, variance, inheritance, interfaces,
  user-defined capabilities or traits.
- A lambda cannot call a function that declares `throws`, so a step that can
  fail still needs a `for` loop.
- The language server renames local variables and parameters only. Its
  references search open files and files of the same project that mention the
  name, up to 200 files.
- There is no central package registry or publishing service, and the
  compiler is not self-hosted.
- Java reference results are conservatively nullable. Java arrays are opaque
  boundary values, and arbitrary Java wildcard, varargs and SAM interop is not
  supported. Some Java libraries require explicit glue or are not yet callable.
- Numeric types and checked integer operations do not prove scientific
  algorithms stable, correctly conditioned, unit-safe, or reproducible across
  all JVMs.
- A green test suite covers the documented contracts and tested workflows; it
  does not prove every application correct.

See `docs/KNOWN_LIMITATIONS.md`, `docs/FEATURE_STATUS_IMPLEMENTED.md`, and the
versioned output of `sprig capabilities --json` before relying on a particular
feature. Every change since v0.5.0-beta.1 is listed in the
[comparison](https://github.com/ColinHouse/Sprig/compare/v0.5.0-beta.1...v0.6.0-beta.1).
