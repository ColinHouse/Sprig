# Sprig v0.7.0-beta.1

Sprig **v0.7.0-beta.1** is the third Beta SDK. Lambdas can now call functions
that fail, Sprig function values can be passed to Java callbacks and varargs,
the standard library gains sets, random values, regular expressions, dates and
a test runner, and the compiler's errors and help teach the language to
someone who has never seen it. It is an experimental Beta, not a promise of
production stability or a frozen API. The compiler is **0.7.0-beta.1**; the
language version remains **0.8-dev**. JDK 17+ is required. Linux and macOS are
release-supported; Windows remains an experimental, non-blocking preview.

Some changes reject code that v0.6.0-beta.1 accepted. Read the upgrade
section below before upgrading a project.

## Highlights

### Lambdas that can fail, and `rethrows`

- A lambda may call a function that throws `Error`, and its type then says so:
  `fn(T) -> R throws Error`. Reading a list of records no longer needs a `for`
  loop and a `MutableList`:

  ```sprig
  func tasks(entries: List[codec.Object]) -> List[Task] throws Error:
      return entries.map(fn(entry: codec.Object) => task(entry))
  ```

- A function type may declare `throws Error`. A value without the clause is
  accepted where the clause is expected, never the reverse
  (`SPR-TYPE-CALLABLE-THROWS`).
- A function declared `rethrows` throws exactly what its callable arguments
  throw. The `@std/lists` helpers that take a function (`sort_by`, `group_by`,
  `fold`, `find`, `any`, `all`, `count`, `sum_by`) are `rethrows`, so passing
  a lambda that cannot fail is still an ordinary call. A `rethrows` function
  needs such a parameter (`SPR-FLOW-RETHROWS`).
- Only `Error` crosses a function value. A checked Java exception is still
  handled in a named function.

### Java callbacks and varargs

- A Sprig function value can be passed where Java expects a functional
  interface with at most three parameters:

  ```sprig
  names.sort(fn(a: String, b: String) => CharSequence.compare(a, b))
  names.forEach(fn(name: String) => print(name))
  ```

  `List.removeIf`, `Map.forEach` and `Thread(Runnable)` work the same way. A
  wildcard inside the interface's type arguments (`Consumer<? super E>`) reads
  as its bound. A value whose type declares `throws Error` cannot be passed to
  Java.
- A varargs parameter takes the trailing arguments or one Java array:
  `Path.of("etc", "sprig", "config.json")`, `Files.exists(config)`,
  `String.format(...)`, `String.join(...)`. A type-variable element (`T...`)
  is still unsupported.
- `sprig api` reports the new `java-callable` interop level, and
  `sprig capabilities` sets `jvmVarargs` and `jvmFunctionalInterfaces`.

### Standard library

| Module | What's new |
|---|---|
| `@std/sets` (new) | `Set[T]` in insertion order: `add` and `remove` report whether anything changed, `has`, `size`, `to_list`; `of`, `union`, `intersection`, `difference` |
| `@std/random` (new) | `seeded(seed)` for a repeatable sequence or `fresh()`; `next_int`, `next_float`, `next_bool`, `shuffled`, `choice`, `uuid`. Not for secrets |
| `@std/regex` (new) | `matches`, `find`, `find_all`, `replace_all`, `split` with Java's pattern syntax; an invalid pattern is an `Error` |
| `@std/dates` (new) | ISO dates as text: `today_utc`, `parse`, `is_valid`, `plus_days`, `days_between`, `day_of_week`, `year`, `month`, `day` |
| `@std/test` | `check(name, body)`, `check_error[T]` and `finish()` run named checks, report every failure and set the exit status; `equal[T]` compares any value that supports `==` |
| `@std/process` | `run(command)` runs an argv vector with no shell, captures UTF-8 output, and returns a nonzero exit status as an ordinary value |
| `@std/lists` | `first`, `last`, `take`, `drop`, `reversed`, `distinct`, `index_of`, `enumerate`, `zip` |
| `@std/text` | `strip_prefix`, `strip_suffix`, `fixed(value, decimals)`, which rounds half away from zero |
| `@std/files` | `read_lines`, `walk`. Every failing function now throws `Error` with the operation, the path and a plain reason: `cannot read data/x.txt: no such file` |
| `@std/time` | `sleep`, `monotonic_nanos` |

Every function that can fail declares `throws Error`; invalid input such as
`next_int(0)`, `take(items, -1)` or an invalid date is rejected before Java
sees it.

### Errors and help that teach Sprig

We gave a local 9B model a small task and only the `sprig` command. It never
got a 30-line program to compile in ten attempts, while the same task in Java
passed at once. Each step of that transcript became a fix:

- Habits from other languages get the Sprig spelling where they are reported:
  - `else if` (Sprig writes `elif`), a declaration without a value, `++`,
    `List<Int>`, braces around a block, and `//` comments;
  - one-line and C-style `if`, `0..n`, and `def`, `function` or `public class`;
  - `catch _:`, and `readLine()`, `int()`, `len()`, `True` and `None`;
  - the types `str`, `int` and `boolean`, and an unimported `Math` or `Scanner`.
- Hints name the exact repair. A function header without a result type reports
  `'func main()' has no result type; write 'func main() -> Unit:'`. Integer
  division suggests `sum.toFloat() / count.toFloat()`. An undeclared `Error`
  shows the enclosing header with `throws Error` added.
- `help language` is a complete small program that reads standard input.
  `strings`, `collections` and `numerics` list their built-in methods, and
  text help prints each example's source. `help modules` lists the bundled
  `@std` modules, and an unknown topic lists the topics.
- `sprig run` says so when nothing ran because no statement calls `main`. An
  overflow at run time says how to check for it or catch it.
- Text output shows a repeated hint once, and only the first syntax error on a
  line. These changes touch messages, hints and help only; diagnostic codes and
  the JSON format are unchanged.

### Type checking

- A top-level `let` narrows after an early exit (`if x == null: throw ...`), as
  it already did in a function body.
- Two flow checks for checked Java exceptions: a `catch` that nothing in its
  `try` can throw is `SPR-FLOW-CATCH-NEVER-THROWN`, and a declared exception
  the body never throws is `SPR-FLOW-THROWS-UNUSED`. `Exception` and
  `Throwable` are exempt.
- A `Unit` result used as a value is `SPR-TYPE-UNIT` at that expression. Before,
  such programs passed `sprig check` and failed in `javac`. The cases covered
  are member access, list and map elements, `==` operands, Java arguments and
  `return noop()` in a `Unit` function.

### Projects

- `sprig check --bin NAME` and `sprig build --bin NAME` select a `[[bin]]`, as
  `run --bin` does.
- In a project with several bins and no `[project] entry`, `sprig check` with
  no file checks every bin. A module the bins share reports its problems once,
  and `--json` lists the checked bins in `bins`. `build` and `run` still need
  `--bin` there, and their error names the choices.
- An explicit `.spr` file inside a project wins over the bins and still
  compiles against the locked dependencies.

## Upgrade from v0.6.0-beta.1

On a managed Linux/macOS installation, run `sprig upgrade --check` and then
`sprig upgrade`. The installer verifies the published checksum and archive
before switching SDKs; older installed versions remain available. A manual
installation can use the ZIP and `.sha256` file from the
[release page](https://github.com/ColinHouse/Sprig/releases/tag/v0.7.0-beta.1).

Then run `sprig resolve` in each project root. A lock records the compiler
that wrote it, so a lock from v0.6.0-beta.1 is reported as
`SPR-PROJECT-LOCK-STALE`.

Changes that can reject code that compiled before:

- **`@std/files` throws only `Error`.** A `catch problem: IOException` around a
  `@std/files` call no longer compiles, because nothing in the `try` can throw
  it. Catch `Error` instead; `problem.message` names the operation, the path
  and the reason. A function that declared `throws IOException` only for these
  calls should declare `throws Error`.
- **Catch and throws clauses that cannot happen are errors.** For checked Java
  exceptions other than `Exception` and `Throwable`, remove a `catch` reported
  as `SPR-FLOW-CATCH-NEVER-THROWN` and a `throws` entry reported as
  `SPR-FLOW-THROWS-UNUSED`.
- **`rethrows` is a keyword.** Rename any identifier with that name.
- **Project selection.** A file and `--bin` given together are an option error
  (exit 2). Before, one of them was ignored, depending on where the file was.

Diagnostic messages and hints changed wording for many mistakes. Existing
codes, phases and exit statuses keep their meaning, so tools should match on
codes. Re-run your
project's checks and tests after upgrading.

## Known limits

- This is an experimental Beta, not production-ready software or a guarantee of
  source, binary, or API stability.
- Windows is not release-supported.
- Generic calls need explicit type arguments, such as `lists.find[Order](...)`.
  There is no generic type inference, variance, inheritance, interfaces,
  user-defined capabilities or traits.
- A lambda has a single expression as its body and may throw only `Error`. A
  checked Java exception is handled in a named function.
- A Java functional interface is accepted with at most three parameters, and
  its type variables are bound only through the receiver or explicit type
  arguments. Wildcards outside a functional interface's type arguments,
  type-variable varargs and generic arrays remain unsupported. Java arrays are
  opaque values, and Java reference results are conservatively nullable.
- The language server renames local variables and parameters only.
- There is no central package registry or publishing service, and the
  compiler is not self-hosted.
- Numeric types and checked integer operations do not prove scientific
  algorithms stable, correctly conditioned, unit-safe, or reproducible across
  all JVMs.
- A green test suite covers the documented contracts and tested workflows; it
  does not prove every application correct.

See `docs/KNOWN_LIMITATIONS.md`, `docs/FEATURE_STATUS_IMPLEMENTED.md`, and the
versioned output of `sprig capabilities --json` before relying on a particular
feature. Every change since v0.6.0-beta.1 is listed in the
[comparison](https://github.com/ColinHouse/Sprig/compare/v0.6.0-beta.1...v0.7.0-beta.1).
