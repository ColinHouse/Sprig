# Test layout

Run everything with `./scripts/test.sh` from the repository root (`python3
scripts/test.py` on any platform). The exact suite inventory lives in
`scripts/test.py` and is canonical for contributors; this page explains the
layout. Tiers mirror the four evidence levels — parser acceptance, static
checking, `javac` success, runtime behavior — and are never conflated.

| Directory | Level | How it is checked |
|---|---|---|
| `syntax/positive` | lexer/layout/parser accepts | `sprig check --syntax-only` |
| `syntax/negative` | lexer/layout/parser rejects with `SPR-LEX-*`/`SPR-SYNTAX-*` | same, expects nonzero exit |
| `semantics` | name resolution + type checking | `sprig check --json`, expected code from `cases.json`, JSON schema validated |
| `runtime` | javac + JVM behavior | `sprig run`, stdout diffed against `*.out`; `shapes.spr` is an import dependency |
| `visitor` | compiler-style programs written in Sprig | goldens + exhaustiveness regression |
| `numeric` | static numeric errors, checked runtime arithmetic, JVM interop, scientific precision | `python3 numeric/check_numeric.py`, independent Python decimal/integer oracle and fixed seed `0x5A17` |
| `correctness` + `review_cases` | Java nullability/effects, `Unit`, generic arity, inferred-case `match`, JSON CLI results | `python3 correctness/check_correctness.py` |
| `recovery` | structured diagnostics for incomplete input and truncation prefixes | `python3 recovery/check_recovery.py` |
| `formatter`, `reexports`, `match_expression` | the #34 features, including byte-level and mutation checks | the sibling `check_*.py` suites |
| `adversarial/v08`, `adversarial/regressions` | independent attacks on generics, naming, layout, JVM metadata, installer and SDK composition | `check_generics.py`, `check_projects.py` and the seven `regressions/check_*.py` suites |
| `callables`, `bootstrap` | Sprig/JVM callable bridges and the stage-1 frontend probe | `check_callables.py`, `check_probe.py` |
| `cli_contract`, `cli_library` | rejected CLI options and the Sprig-written CLI library | `check_cli_contract.py`, `check_cli_library.py` |
| `project`, `project_deps`, `maven` | project model, lockfiles, local/Git/Maven resolution and offline cache | the sibling `check_*.py` suites |
| `installer`, `upgrade`, `dogfood` | managed SDK install/switch/refusal and PATH-only installed-SDK use | the sibling `check_*.py` suites |
| `web`, `sqlite`, `stdlib` | real HTTP/JDBC adapters, migrations and standard-module contract fixtures | `check_web.py`, `check_sqlite.py`, `check_migrations.py`, `scripts/test-stdlib.py` |
| `agent_tooling`, `agent_eval` | `capabilities`/`help`/`api`/`explain`, Sprig-written tools and the deterministic task pack | the sibling `check_*.py` suites |
| `release_hardening` | bundled `@std`, traversal/shadow refusal, lock integrity | `check_hardening.py` |
| `ergonomics` | optional mutation gate; rebuilds the compiler per mutation and restores sources, so it is never part of concurrent verification | `python3 ergonomics/check_mutations.py [name ...]` |

The `syntax/` fixtures and the original semantic cases match the design kit in
`spec/`; `semantics/cases.json` extends them with the cases added by this
implementation. The design kit's own copies were removed during the
publication cleanup because this directory is the executable superset.

The focused correctness suite checks diagnostic codes and, for selected
minimal fixtures, verifies that no secondary diagnostic is emitted. Runtime
goldens were generated by the compiler and reviewed against the intended
semantics before being committed. Recorded exit codes, JSON envelopes and
program output are contract evidence; do not update a golden to hide a
behavior change (see `AGENTS.md`).
